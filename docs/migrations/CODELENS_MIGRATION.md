# CodeLens AI 迁移说明

最后更新：2026-09-04
状态：进行中；源仓库保留，不删除、不归档

## 结论

`ai-develop` 不是 `codelens-ai` 的完整副本。两者在 AI 对话与 Agent 概念上有重叠，但代码、技术栈和完成度不同。迁移采用“提炼能力、重新实现、逐项验收”的方式，不直接合并 Git 目录，也不以存在相似代码作为删除源仓库的依据。

## 仓库定位

| 能力 | `codelens-ai` | `ai-develop` 迁移目标 | 当前状态 |
|---|---|---|---|
| 流式对话 | 已有 SSE 与模型调用 | 服务端控制的稳定 SSE 协议 | 协议与测试完成，真实模型待接入 |
| 前端工作台 | 静态 HTML/CSS/JavaScript | React + TypeScript 工作台 | 未迁移 |
| Agent/Skills/Rules | 前端内置多套配置 | Java 编排与可审计配置 | 未迁移 |
| 项目上下文 | 主要由前端配置和用户输入提供 | 服务端按需组装项目文件、规则、工具结果和历史 | 已纳入规划 |
| Git 历史 | 54 个提交及独立开发分支 | 保留来源与迁移证据 | 源仓库继续保留 |

## 安全约束

- 新接口只接收用户消息，不接收客户端提供的 `baseUrl`、API Key、模型名称或系统提示词。
- 提供商凭据只存在于服务端环境配置中，不记录到日志、指标标签、异常消息或数据库明文。
- 不复制源仓库历史 `.env` 或任何真实凭据。
- 源仓库历史提交曾暴露 Xiaomi MiMo API Key。必须在提供商控制台撤销或轮换；重写 Git 历史、删除文件或归档仓库都不能使已泄露密钥自动失效。
- 用户鉴权、会话归属和多租户隔离完成前，对话接口仅用于本地开发验证。

## 分阶段执行

1. **安全协议骨架（已完成）**：建立 `ChatGateway`、单消息请求、结构化 SSE 事件、超时取消、指标和自动化测试。
2. **真实模型接入（待确认）**：选择模型提供商，通过服务端配置实现网关，并补充超时、限流、费用与内容安全测试。
3. **上下文与 Skills（未开始）**：按需读取项目文件、压缩会话、限制上下文预算，并把旧项目 Agent 配置转为可发现、可版本化的 Skills。
4. **前端能力重建（未开始）**：盘点旧前端交互，在 React + TypeScript 中按需重建；不原样搬运客户端密钥配置。
5. **迁移验收（未开始）**：功能、测试、安全、历史和文档全部通过后，由维护者人工决定是否归档源仓库。

## 源仓库归档门槛

- 迁移清单逐项确认，旧仓库仍有而新仓库缺失的能力已明确保留或放弃。
- 新仓库全量测试、构建和最小运行验收通过。
- 源仓库 54 个提交与分支历史仍可恢复，并记录新旧仓库关系。
- 历史泄露密钥已在提供商侧撤销或轮换。
- [x] `ai-develop` 已使用 noreply 身份建立私有 GitHub 仓库并同步 `main` 基线。
- 维护者再次明确批准归档；未满足时保持两个仓库并存。

## 风险与待办

- 模型提供商、预算和网络条件尚未确定，真实回答能力仍被阻塞。
- 当前 SSE 是单轮无状态实现，不能宣称已迁移旧项目的会话体验。
- 旧前端包含较多产品交互，重建前需要做页面和配置能力清单，避免遗漏。
- 新仓库当前保持私有；改为公开前必须再次执行敏感信息、历史和文档链接检查。
